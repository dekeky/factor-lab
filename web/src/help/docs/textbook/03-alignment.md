因子算错方向，乘 `-1` 就能拧回来。用了未来的信息，样本内会漂亮，换一段行情或一上模拟盘就垮。这一章把评价引擎的时间口径固定下来。

## 1. 信号日只能看当天及以前

对每个交易日 `t`：

1. 用 `t` 及以前的数据计算因子值（收盘后才能拿到当天的 `close`、`vol`）。
2. `t+1` 日收盘买入。这样不会用「当天收盘价」既打分又成交。
3. 持有 `H` 个交易日，在 `t+1+H` 日收盘卖出。`H` 默认 1。

前向收益（评价引擎写死的公式，表达式里不要再手动「减一天」）：

```
fwd_ret(t) = close(t+1+H) / close(t+1) - 1
```

时间线：

```
t 收盘后出因子值
    → t+1 收盘买入
        → t+1+H 收盘卖出
```

## 2. 为什么是 t+1 收盘，不是 t 收盘

如果你在 `t` 日收盘价上算出因子，又假设 `t` 日收盘能按这个价格买进，等于用了当时还没有的成交结果。这叫前视偏差（look-ahead）。

本平台评价一律按上面的 `fwd_ret` 对齐。模拟盘更严：信号日选出标的，**下一交易日开盘**才成交，还要过涨跌停、停牌、100 股整手。评价回答「有没有截面预测力」；模拟盘回答「按交易约束记账，净值怎么走」。两者不要混着看。

## 3. 价格用后复权

Tushare 源写入 DSL 的 `open` / `high` / `low` / `close` 是**后复权**价。除权除息之后，历史价格被抬到和今天可比的尺度，动量、均线才不会在除权日跳一把。

`pct_chg` 不是 Tushare 接口里那个原始字段，而是：

```
pct_chg(t) = close(t) / close(t-1) - 1
```

单位是小数：`0.02` 表示上涨 2%，**不是**百分数 2。写成 `pct_chg > 2` 几乎永远为假。

模拟盘成交用另一组内部列（前复权开盘等），DSL 里引用不到，也不该引用。

## 4. 财务数据按公告日生效

`roe` 按**公告日**对齐（point-in-time），不是按报告期。2024 年年报若 2025-03-31 才公告，2025-03-30 的因子不能用这个年报。

用报告期对齐会把当时市场上还不知道的利润写进历史因子，这是财务因子最常见的前视。平台已经按公告日处理；你要做的是：不要在表达式里再「手工提前一期」。

## 5. 持有期 H 改什么

评价参数里的持有期就是这里的 `H`。

| H | 在检验什么 |
| --- | --- |
| 1 | 次日截面收益，噪声大，换手高 |
| 5 | 大约一周，常用来看短逻辑是否还在 |
| 20 | 大约一个月，换手下降，IC 通常变小 |

同一条公式，H 从 1 改到 20，RankIC 变小是正常的。若 H 一变符号就反，说明这条信号不稳定，不要在参数上搜。
