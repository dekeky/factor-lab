factor-lab 技术概览

单机可部署的 AI 辅助 A 股因子研究平台。研究者用一门受限 DSL 写因子，系统在真实行情上完成静态校验、前向收益评价、分层回测、因子组合与纸上模拟交易；AI 只负责把自然语言翻译成候选表达式，不参与打分、不接触评价口径、不写库。

03

因子语言与计算内核

一门受限、可静态校验的表达式语言，而不是通用脚本。所有算子输出统一的列向量，缺失值语义全局一致。

DSL 示例

# 中间变量 = 赋值；最后一行即因子值
mom20 = close / ts_delay(close, 20) - 1
alpha = -1 * cs_rank(mom20)

# if 是注册算子，不是控制流关键字
down  = if(pct_chg < 0, ts_std_dev(pct_chg, 20), close)
alpha = cs_rank(ts_arg_max(down * down, 5)) - 0.5

静态校验硬约束：算子白名单、参数个数、窗口常数必须 1~512 整数、字段/变量先定义后使用、变量名不得与字段重名、嵌套 ≤ 64 层。Parse / Validate 返回错误列表而非首错即停。

算子库（实测 28 个）

执行器逐 AST 节点产生长度 T×N 的列向量；算术任一 NaN 即 NaN，比较/逻辑把 NaN 当假，滚动与截面聚合跳过 NaN。计算内核不并发，并发在 API 层（批量评价 4 路）。

评价与组合：口径锁死

只有口径写死，不同因子、不同人、不同时间做出的结果才可比较。

唯一收益对齐公式

信号日 t 只用 t 及以前数据；t+1 收盘执行；持有 H 个交易日
fwd_ret(t) = close(t+1+H) / close(t+1) - 1
lastSignal  = T - 2 - H
参数默认可经 API 覆盖
Horizon 持有期1是（≥1）
Groups 分层数10是（≥2）
Cost 单边成本0.003是（≥0）
MinStocks 最小截面5否
基准 / 主口径全市场等权 / 多头净超额

输出 IC、RankIC、ICIR、t 值、P(IC>0.02)、分层净值、多头毛/净净值、换手与年化成本。退化截面跳过 IC 统计但照常推进净值，有专门回归测试。

组合：复用同一引擎，不另起炉灶

# [1] 因子名  weight=0.5000
p0_mom20 = close / ts_delay(close, 20) - 1
z0 = cs_zscore(-1 * cs_rank(p0_mom20))
alpha = z0 * 0.500000 + z1 * 0.500000
  • 变量隔离：中间变量加 pN_ 前缀重命名，函数名不误改
  • 标准化：终值 cs_zscore × 权重 × 方向，按 Σ|w| 归一化；上限 20 个成分
  • 同质化告警：逐日 Spearman 秩相关取均值，> 0.7 提示「高度同质，分散效果有限」
  • 生成的仍是 DSL，交给同一个 engine.Run + eval.Evaluate
05

AI 辅助：提议 / 裁决分离

最值得对外讲的一条架构纪律：LLM 的输出永远不是可执行结果。

闭环流程

prompt
运行时注入 当前面板字段 + 算子白名单；combo 模式只给因子库元数据，禁止发明因子
LLM
Eino 接 OpenAI 协议端点（DeepSeek 等），要求严格 JSON；流式增量只推 reply 给用户
parse
自研平衡括号 + 字符串感知的 JSON 提取，兼容围栏与前后文字
裁决
factor → engine.Check（与 /api/check 同一函数）；combo → 白名单校验（id 可用、去重、≥2 个）
失败
把具体错误原文回灌下一轮重试，最多 3 次 LLM 调用
通过
done 返回候选，由用户确认后才应用到编辑器
边界：全程不调用 eval.Evaluate、不写库、不执行工具；模型看不到也改不了评价口径。未配置模型时一次性接口与 WS 升级前均返回 503，代码中不存在任何模板降级生成器。

实盘模拟：任务化的 T+1 撮合

从「打开页面把整段历史重跑一遍」重构为持久化、可恢复、幂等的事件驱动模型。River 队列 + SQLite，领域层与编排层彻底分离。

五包分层

  • account 冻结的账户实体
  • matching 纯撮合函数，不碰 DB / 队列
  • ledger 只改内存账本
  • jobs River worker，只做编排与事务
  • store SQLite + 内嵌 schema

Generate 与 Execute 互不调用；HTTP 不写成交；GET 全为 SELECT。

四层幂等

  • River ByArgs 任务去重
  • plan 唯一索引 (account_id, substr(exec_at,1,10))
  • snapshot 主键 (account_id, date)
  • 条件更新 WHERE status='pending'

缺数 JobSnooze(1min) 自愈，不写计划不改账；重启后 River 自动接管，无需 kick。

撮合口径

  • 默认 TopN 10 / 阈值 20 / 本金 100 万 / 单边 0.3%
  • 权重偏移 > 3% 触发 rebalance
  • 股数按信号日收盘估算，向下取整 100 股
  • 先卖后买；现金不足每次减 100 股
  • 停牌 / 涨跌停 / 缺价记 skipped_*，不换股顶替

架构级边界

级别缺口建议

研究能力边界与实现注意点

  • 股票池为指数成分，历史成分取最近一期权重，长区间存在幸存者偏差；全 A 股约 5000 只未压测
  • 缺 cs_neutralize，未做行业/市值中性化；未做 winsorize 与分组稳健性检验
  • 成交价为开盘/收盘单价，无 VWAP、无盘中分批撮合
  • /api/paper/*/sync 当前为 204 空实现，缺数由 worker 每分钟自愈
  • TopNavNet 换手计算比较同一份当期持仓，与 TopNav 数值相同；换手/成本指标本身正确
  • AI 的 90s 超时为硬编码，不随设置中的 TimeoutSec 变化

快速复现

单二进制启动，不需要任何中间件。Windows 下双击 start.bat 即可。

# 编译
go build -o factor-lab.exe ./cmd/server
npm --prefix web ci && npm --prefix web run build

# 生产启动（Tushare Pro 真实 A 股数据）
./factor-lab.exe -addr 127.0.0.1:8080 \
  -data tushare -index 000300.SH -topn 0 -start 20200101 \
  -store data/factors.json -web web/dist \
  -api-token "$FACTOR_LAB_TOKEN"

# 验证
go test ./...
curl -s http://127.0.0.1:8080/api/health
curl -X POST -H "X-API-Token: $TOKEN" http://127.0.0.1:8080/api/admin/reload

环境变量：TUSHARE_TOKEN、FACTOR_LAB_TOKEN、LLM_BASE_URL/LLM_API_KEY/LLM_MODEL。Tushare token 与模型也可在界面左下角「设置」里填，写入 data/settings.json，保存即热生效。鉴权：浏览器登录后用 HttpOnly Cookie（fl_session，12h，SameSite=Strict），脚本用 X-API-Token 头。
